# Security policy

## Поддерживаемые версии

Исправления безопасности выпускаются для последней версии `arm_info` в ветке `main`.

## Отчёты содержат инфраструктурные данные

Обычный TXT/JSON-отчёт может содержать hostname, IP/MAC/DNS, шлюз, домены SSSD, пути/URI SMB и сертификатов, имена почтовых серверов, Subject/Issuer и printer backend URI. **Не публикуйте необезличенный отчёт в Issues.** Для публичного отчёта используйте:

```bash
sudo arm_info --privacy
```

или:

```bash
sudo arm_info --privacy --json
```

Для корпоративного отчёта:

```bash
sudo arm_info --corp --privacy
sudo arm_info --corp --privacy --json
```

Privacy уменьшает раскрытие штатных диагностических полей, но не является формальной анонимизацией произвольных строк журнала. Перед передачей отчёт необходимо просмотреть. Mail-профиль не принимает URI с credentials, не читает пароль, не аутентифицируется и не отправляет письмо.

## Запуск от root

Для полной диагностики SMART и DMI скрипт обычно запускается от root. Конфигурация `/etc/arm_info.conf` не исполняется через `source`: читается только белый список поддерживаемых ключей.

По умолчанию autofs-карты разбираются пассивно. `--probe-autofs` может инициировать автомонтирование и должен использоваться только осознанно. Команды из рекомендаций не выполняются автоматически; изменяющие состояние действия маркируются `ИЗМЕНЯЕТ СОСТОЯНИЕ`.

## Сообщение об уязвимости

Не публикуйте рабочий эксплойт или чувствительные данные в открытом Issue. Создайте Issue без секретных деталей с просьбой связаться для private disclosure либо используйте GitHub Private Vulnerability Reporting, если он включён для репозитория.
