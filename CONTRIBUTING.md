# Участие в разработке

Спасибо за вклад в `arm_info`.

## Перед PR

1. Создайте отдельную ветку (`fix/...`, `feature/...`, `docs/...`).
2. Не добавляйте в тесты реальные hostname, домены, IP, MAC и другие внутренние данные.
3. Выполните:

```bash
make check
make test
```

4. Если меняется логика индекса, обновите `docs/SCORING.md`.
5. Если меняется пользовательский интерфейс, обновите README, `docs/USAGE.md` и CHANGELOG.

## Коммиты

Рекомендуемый стиль:

```text
feat: add JSON output
fix: correct NVMe health parsing
docs: clarify scoring model
chore: update CI
```

## Требования к изменениям диагностики

Новый показатель должен иметь понятный источник данных, описание ограничений, минимизацию ложных срабатываний и рекомендацию в формате «влияние → действие → команда». Нельзя выдавать неизвестное значение за `100/100`.
