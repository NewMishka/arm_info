# Расчёт технического индекса

Индекс `0..100` предназначен для приоритизации технических рисков. Это не процент физического «здоровья» всего ПК и не прогноз даты отказа.

## Вес групп

| Группа | Вес |
|---|---:|
| Накопители | 40% |
| Файловые системы | 15% |
| Стабильность системы | 15% |
| Оперативная память | 10% |
| CPU / температура | 10% |
| Возраст / наработка | 5% |
| Сеть | 5% |

### Накопители

Учитываются SMART health, ресурс SSD/NVMe, температура, Power-On Hours, reallocated/pending/uncorrectable, NVMe Critical Warning/Media Errors и состояние software RAID.

Начиная с 1.2.3 физический накопитель, на котором находится корневая ФС, определяется через `findmnt`/raw `lsblk` и считается системным. Его оценка имеет 80% веса внутри storage-группы; худший **известный** дополнительный внутренний диск — 20%. Если дополнительных внутренних дисков нет или их SMART неизвестен, storage score определяется системным накопителем.

Съёмные/USB-носители и оптические устройства выводятся для инвентаризации, но не участвуют в storage score, SMART completeness и эксплуатационном возрасте АРМ. Если системный диск определить не удалось, применяется fallback по внутренним несъёмным дискам.

### Файловые системы

Проверяются корневая и локальные файловые системы на внутренних накопителях: заполнение, inode и read-only. ФС на съёмных/USB-носителях не участвуют в `Макс. заполнение`, inode-score и read-only штрафах, чтобы подключённая флешка не меняла техническую оценку АРМ.

По умолчанию пороги задаются `FS_WARN=80`, `FS_HIGH=90`, `FS_CRIT=95`, `INODE_WARN=80`. Read-only корневая FS считается критической.

### ОЗУ

Основной показатель — `MemAvailable`, а не просто `used`. Swap снижает оценку только вместе с дефицитом доступной RAM. Факт OOM существенно снижает score.

### CPU

Температура берётся по трём коротким замерам; для оценки и пользовательского отчёта используется медиана. По умолчанию предупреждение начинается с 80°C. Load сравнивается с числом логических CPU.

### Стабильность системы

Это оценка **устойчивости работы АРМ по системным событиям**, а не утверждение о повреждении или качестве самой установленной ОС. Группа имеет вес 15% в итоговом индексе и начинается со 100 баллов.

Штрафы отображаются непосредственно в текстовом отчёте:

| Сигнал | Условие | Штраф |
|---|---|---:|
| failed systemd units | 1 / 2–3 / >3 | 5 / 10 / 20 |
| hardware/storage errors в kernel journal | 1–2 / 3–5 / >5 | 10 / 20 / 35 |
| уникальные `err..alert` в journal | 6–15 / 16–30 / >30 | 5 / 10 / 15 |
| OOM-killer | обнаружен | 10 |
| синхронизация времени | `Нет` | 5 |
| признаки аварийной предыдущей загрузки | >0 | 5 |
| EDAC/ECC corrected errors (CE) | >0 | 5 |
| EDAC/ECC uncorrectable errors (UE) | >0 | итог stability ограничивается максимум 30 |

Например, 1 failed-служба, 13 hardware/storage errors и 155 уникальных `err..alert` дают `100 - 5 - 35 - 15 = 45/100`. Это означает наличие серьёзных системных событий, требующих разбора; само по себе значение не доказывает неисправность ОС.

### Возраст / наработка

Используется худший доступный эксплуатационный ориентир между возрастом текущей установки ОС и Power-On Hours **системного накопителя**. Если наработка системного накопителя недоступна, используется максимальная доступная наработка внутреннего несъёмного диска. BIOS date не является возрастом ПК и в score не используется.

### Сеть

Для оценки сети RX/TX errors нормализуются на количество пакетов (ppm). Из потерь в score входят `rx_missed_errors` (пакеты, пропущенные host/NIC из-за нехватки RX-ресурсов) и `tx_dropped`. Общий `rx_dropped` остаётся диагностическим: Linux может учитывать в нём пакеты, отброшенные из-за неподдерживаемого протокола или L2-фильтрации, поэтому сам по себе этот счётчик не снижает score и не создаёт WARN. В отчёте отдельно показываются raw `rx_dropped` и учитываемые потери. Gateway и DNS также учитываются.

## Полнота проверки

`confidence` уменьшается, если недоступны SMART системного/внутренних накопителей, температура CPU, journal, systemd, DMI памяти или запуск выполнен не от root. Съёмные и оптические устройства не снижают полноту SMART. При низкой полноте итог помечается `ПРЕДВАРИТЕЛЬНО`.

## Критические override

Критический статус принудительно устанавливается, например, при read-only root, критическом storage score системного диска, почти полностью заполненном root, degraded software RAID или неисправимых ECC errors. Критическое состояние дополнительного внутреннего диска не игнорируется, но не подменяет роль системного накопителя.

## Настройка порогов

Пороговые значения можно изменить в `/etc/arm_info.conf`. Скрипт принимает только разрешённые числовые ключи и не выполняет конфиг как shell-код.
