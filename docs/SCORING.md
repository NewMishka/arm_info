# Логика оценки технического состояния

## Принцип

Индекс `arm_info` — это интегральная оценка текущего состояния АРМ. Он должен напрямую реагировать на износ накопителей, критические SMART-показатели, заполнение файловых систем, дефицит памяти, OOM, температуру CPU, системные ошибки и состояние сети.

Он **не является процентом оставшегося срока службы**.

## Вес групп

- накопители / износ — 40%;
- файловые системы — 15%;
- стабильность ОС — 15%;
- оперативная память — 10%;
- процессор / температура — 10%;
- возраст / наработка — 5%;
- сеть — 5%.

Если SMART недоступен или часть накопителей не отдаёт достоверные SMART-данные, группа накопителей исключается из среднего, а полнота диагностики уменьшается.

## Процессор

Температура CPU:

| Температура | Балл CPU |
|---|---:|
| < 80°C | 100 |
| 80–84°C | 90 |
| 85–89°C | 75 |
| 90–94°C | 55 |
| ≥ 95°C | 30 |

Load Average за 1 минуту сравнивается с количеством логических потоков:

- `Load1 < threads` — без штрафа;
- `Load1 >= threads` — максимум 85;
- `Load1 >= 2 × threads` — максимум 60.

В отчёте строка «Причина снижения» появляется только при фактическом снижении балла.

## Оперативная память

Основной показатель — `MemAvailable`, а не просто `MemFree`.

Высокая занятость swap сама по себе не трактуется как неисправность, если доступной RAM достаточно и OOM не фиксировался. OOM (`Out Of Memory`) означает, что ядро было вынуждено завершить процесс из-за нехватки памяти.

## Стабильность ОС

Стартовое значение — 100. Балл снижается за:

### Failed systemd units

- 1 — минус 5;
- 2–3 — минус 10;
- >3 — минус 20.

### Аппаратные / дисковые ошибки ядра

- 1–2 уникальных — минус 10;
- 3–5 — минус 20;
- >5 — минус 35.

### Уникальные ошибки journal текущей загрузки

- 0–5 — без штрафа;
- 6–15 — минус 5;
- 16–30 — минус 10;
- >30 — минус 15.

### OOM

Факт OOM текущей загрузки — минус 10 и отдельная рекомендация.

## Возраст / наработка

Используется худший из доступных эксплуатационных ориентиров:

- возраст текущей установки ОС;
- максимальная наработка накопителя (`Power On Hours`).

Дата BIOS в расчёт не входит и показывается только справочно.

| Ориентир | Балл |
|---|---:|
| ≤ 3 лет | 100 |
| ≤ 4 лет | 97 |
| ≤ 5 лет | 93 |
| ≤ 6 лет | 88 |
| ≤ 7 лет | 82 |
| ≤ 8 лет | 75 |
| ≤ 9 лет | 68 |
| ≤ 10 лет | 60 |
| > 10 лет | 52 |

Возраст имеет вес только 5%, поэтому исправный старый АРМ не должен автоматически получать плохую итоговую оценку.

## Сеть

Считаются отдельно:

- RX errors;
- TX errors;
- RX dropped;
- TX dropped;
- RX/TX packets.

Относительные значения нормализуются к `ppm` (событий на миллион пакетов). Errors оцениваются строже, чем dropped.

Также учитываются наличие активного IPv4-интерфейса, default gateway и DNS.

## Накопители

### NVMe SSD

Используются, если доступны:

- SMART Health;
- `Percentage Used` → оставшийся ресурс = `100 - Percentage Used`;
- Critical Warning;
- Media and Data Integrity Errors;
- Available Spare / Threshold;
- температура;
- Power On Hours.

### SATA SSD

Используются SMART Health и распространённые vendor-specific атрибуты остаточного ресурса, если они присутствуют. Поскольку производители кодируют ресурс по-разному, неизвестные значения не подменяются фиктивным процентом.

### HDD

Контролируются SMART Health, Reallocated Sector Count, Current Pending Sector и Offline Uncorrectable, а также температура и наработка.

## Файловые системы

Проверяются локальные ФС. В расчёт входят:

- процент занятого места;
- процент использованных inode;
- режим read-only.

Корневая ФС в read-only, критически заполненный корень и тяжёлое состояние накопителя могут принудительно повысить итоговый статус до критического независимо от среднего балла.

## Полнота проверки

Полнота уменьшается, если отсутствуют важные источники данных: `smartctl`, CPU temperature, журнал, systemd, DMI ОЗУ, возраст/наработка или запуск выполнен не от root.

При полноте <80% итоговый статус маркируется как предварительный.
