# Расчёт технического индекса

Индекс `0..100` предназначен для приоритизации технических рисков. Это не процент физического «здоровья» всего ПК и не прогноз даты отказа.

## Вес групп

| Группа | Вес |
|---|---:|
| Storage | 40% |
| Filesystem | 15% |
| OS stability | 15% |
| Memory | 10% |
| CPU | 10% |
| Age/work hours | 5% |
| Network | 5% |

### Накопители

Учитываются SMART health, ресурс SSD/NVMe, температура, Power-On Hours, reallocated/pending/uncorrectable, NVMe Critical Warning/Media Errors и состояние software RAID. Начиная с 1.2.3 физический накопитель, на котором находится корневая ФС, определяется через `findmnt`/`lsblk` и считается системным. Его оценка имеет 80% веса внутри storage-группы; худший **известный** дополнительный внутренний диск — 20%. Если дополнительных внутренних дисков нет или их SMART неизвестен, storage score определяется системным накопителем.

Съёмные/USB-носители выводятся для инвентаризации, но не участвуют в storage score, SMART completeness и эксплуатационном возрасте АРМ. Если системный диск определить не удалось, применяется прежний fallback по внутренним несъёмным дискам.

### Файловые системы

Проверяются корневая и локальные файловые системы на внутренних накопителях: заполнение, inode и read-only. ФС на съёмных/USB-носителях не участвуют в `Макс. заполнение`, inode-score и read-only штрафах, чтобы подключённая флешка не меняла техническую оценку АРМ. По умолчанию пороги задаются `FS_WARN=80`, `FS_HIGH=90`, `FS_CRIT=95`, `INODE_WARN=80`. Read-only корневая FS считается критической.

### ОЗУ

Основной показатель — `MemAvailable`, а не просто `used`. Swap снижает оценку только вместе с дефицитом доступной RAM. Факт OOM существенно снижает score.

### CPU

Температура берётся по трём коротким замерам; для оценки и пользовательского отчёта используется медиана. По умолчанию предупреждение начинается с 80°C. Load сравнивается с числом логических CPU.

### Стабильность

Учитываются failed systemd units, уникальные hardware/storage errors в kernel journal, уникальные `err..alert`, OOM, проблемы синхронизации времени, признаки аварийной предыдущей загрузки и EDAC/ECC.

### Возраст / наработка

Используется худший доступный эксплуатационный ориентир между возрастом текущей установки ОС и Power-On Hours самого наработанного диска. BIOS date не является возрастом ПК и в score не используется.

### Сеть

RX/TX errors и dropped нормализуются на количество пакетов (ppm). Это корректнее абсолютного накопленного счётчика. Gateway и DNS также учитываются.

## Полнота проверки

`confidence` уменьшается, если недоступны SMART, температура CPU, journal, systemd, DMI памяти или запуск выполнен не от root. При низкой полноте итог помечается `ПРЕДВАРИТЕЛЬНО`.

## Критические override

Критический статус принудительно устанавливается, например, при read-only root, критическом storage score, почти полностью заполненном root, degraded software RAID или неисправимых ECC errors.

## Настройка порогов

Пороговые значения можно изменить в `/etc/arm_info.conf`. Скрипт принимает только разрешённые числовые ключи и не выполняет конфиг как shell-код.
