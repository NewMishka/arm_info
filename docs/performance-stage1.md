# Первый этап оптимизации

База: `5ccfd36c449ae4c37b60e7db9787bb3c911b4478`.
Ветка: `refactor/stage1-performance`.

## Изменения

- TXT: определение ширины один раз на отчёт, выравнивание встроенными
  командами Bash без command substitution, короткие строки без запуска fold.
- Длинные строки и управляющие символы по-прежнему обрабатывает fold.
  Байтовая проверка коротких строк консервативна, включая UTF-8.
- NetworkManager: кэш свойств по UUID и имени поля на время одного вызова
  check_network. Пустые результаты также кэшируются. Старый fallback nmcli
  сохранён. Между вызовами сборщика кэш не сохраняется.
- Схема JSON, CLI и правила диагностических статусов не изменены.

## Проверка

`make test` проходит: новые тесты плюс все прежние наборы CLI, enterprise,
обнаружения DC/GVFS/autofs, рекомендаций, разделов и CIFS.

Новые тесты сравнивают вывод побайтово с эталонами до рефакторинга:
C/UTF-8, шесть ширин терминала, пустые значения, длинные строки, кириллица,
CJK/emoji, табуляция и переносы. Проверяется один запрос ширины на отчёт,
1000 строк без внешних команд форматирования для короткого текста,
разделение кэша по UUID, пустые значения, ошибки nmcli, escaped fallback
и очистка кэша между сборами. Эти проверки подключены к GitHub CI;
локальный прогон не заменяет выполнение GitHub CI.

Эталонные файлы намеренно содержат пробелы выравнивания и исходные
байты вывода fold. Не переформатировать их текстовым редактором.

## Замеры

Контейнер разработки, три запуска, медиана, C.utf8, ширина 110:

| Проверка | До | После |
|---|---:|---:|
| Форматирование 1000 коротких строк | 4,042 с | 0,130 с |
| Корпоративный TXT, `-c -p` | 0,924 с | 0,435 с |

Синтетический вывод совпал побайтово. Для корпоративного прогона код
завершения остался 2, размер вывода 36311 байт: это диагностика контейнера,
а не подтверждение исправности реального АРМ. Прогон не включает реальные
AD/SMB/NM и не прогнозирует время сетевых ожиданий на РЕД ОС.

Воспроизведение замера форматирования:

```sh
python3 tests/benchmark_render.py
```

CI контролирует число внешних вызовов, а не нестабильный порог секунд.
Тайм-ауты, параллельные проверки, сбор снимка mounts/сессий и объединение
SMART-запросов требуют отдельных изменений и тестов.
