# Второй этап: ограниченные сетевые проверки

База этапа: `41e9735` (`refactor/stage1-performance`).
Ветка: `refactor/stage2-bounded-network`.

## Поведение

- Все найденные по DNS контроллеры остаются в TXT/JSON и сохраняют порядок.
- TCP 88/389 проверяются очередью, по умолчанию не более четырёх проверок
  одновременно и не более трёх секунд на соединение.
- Активные проверки DC, CIFS, autofs при `--probe-autofs` и GIO используют
  общий бюджет 30 секунд. Обнаружение ресурсов выполняется до активной проверки.
- После исчерпания бюджета ресурс получает `N/A` и текст
  `не проверен (лимит времени)`. Это не превращается в ложный `OK` или ошибку
  самого ресурса.
- Общий runner использует GNU `timeout -k 1`. Если `timeout` отсутствует,
  потенциально зависающая команда не запускается без ограничения и результат
  считается неполным.
- Параллельные задачи записывают результаты отдельно; отчёт объединяет их в
  исходном порядке, поэтому скорость завершения узлов не меняет порядок строк.

## Настройка

```bash
sudo arm_info -c -p --network-budget 45 --network-jobs 4
sudo arm_info --profile network --network-budget=60 --network-jobs=6
```

`--network-budget` принимает 1–300 секунд, `--network-jobs` — 1–16.
Значения по умолчанию: 30 секунд и 4 задачи. Те же defaults можно переопределить
переменными `ARM_INFO_NETWORK_BUDGET`, `ARM_INFO_DC_JOBS` и
`ARM_INFO_DC_PROBE_TIMEOUT`; CLI имеет приоритет для первых двух.

## Тесты

`tests/test_stage2_limits.sh` проверяет:

- отсутствие неограниченного fallback при отсутствии `timeout`;
- остановку зависшей команды;
- верхнюю границу параллельности;
- проверку обоих портов каждого DC;
- стабильный порядок и сохранение полного списка из 20 DC;
- общий бюджет и точное количество пропущенных TCP-проверок;
- наследование исчерпанного бюджета SMB-проверкой;
- CLI-границы параметров.

Все тесты первого этапа и прежние регрессионные наборы продолжают выполняться.

| Параллельность | Медиана |
|---:|---:|
| 1 | 1,651 с |

Замер проверяет планировщик, а не реальную сеть. На АРМ итог зависит от DNS,
доступности DC, SMB, числа ресурсов и выбранного бюджета.
