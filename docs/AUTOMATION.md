# Автоматизация

## Exit codes

| Код | Значение |
|---:|---|
| 0 | состояние нормальное и полнота проверки достаточна |
| 1 | есть предупреждения или неудовлетворительное состояние; для `--compare` найдены отличия |
| 2 | критическое состояние |
| 3 | состояние нормальное, но диагностика неполная |
| 64 | ошибка параметров CLI |
| 65 | ошибка разбора JSON при `--compare` |
| 66 | файл сравнения недоступен |
| 69 | отсутствует обязательная зависимость операции, например `python3` для `--compare` |
| 73 | явный путь сохранения корпоративного отчёта недоступен |

## Стандартный JSON — schema v1

```bash
sudo arm_info --json --privacy --no-save
```

Стандартный JSON содержит `schema_version`, системные показатели, scores, confidence, diagnostics и массив `recommendations[]`.

Пример:

```bash
sudo arm_info --json --privacy --no-save | jq '.summary'
```

## Корпоративный JSON — schema v2

```bash
sudo arm_info --corp --privacy --json --no-save
```

Enterprise schema v2 содержит стабильные ключи в `checks[]`, сводку и расширенные `recommendations[]`. Это основной формат для helpdesk, сравнения АРМ и последующей машинной обработки корпоративной диагностики.

`--corp` по умолчанию сохраняет TXT/JSON. Для pipeline в автоматизации обычно удобнее явно добавлять `--no-save`, либо задавать файл через `-o`:

```bash
sudo arm_info --corp --privacy --json --no-save | jq '.summary'
sudo arm_info --corp --privacy --json -o /var/tmp/arm-corp.json
```

## Сравнение двух АРМ

```bash
arm_info --compare arm-a.json arm-b.json
arm_info --compare arm-a.json arm-b.json --json
```

Для enterprise schema сравниваются стабильные ключи `checks[]`. Для стандартной schema выполняется рекурсивное сравнение с исключением очевидно изменчивых полей времени/отчёта. Код `0` означает отсутствие отличий, `1` — отличия найдены.

Для `--compare` требуется `python3`.

## Рекомендации

В стандартной schema v1 рекомендации содержат причины, влияние, проверки, действие, команду и контроль результата. В schema v2 корпоративного профиля команды представлены массивом `commands[]`, что позволяет обрабатывать каждую команду отдельно без парсинга текстового отчёта.
