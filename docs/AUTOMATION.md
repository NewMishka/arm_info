# Автоматизация

## Exit codes

| Код | Значение |
|---:|---|
| 0 | состояние нормальное и полнота проверки достаточна |
| 1 | есть предупреждения или неудовлетворительное состояние; для `--compare` найдены отличия |
| 2 | критическое состояние |
| 3 | состояние нормальное, но диагностика неполная |
| 64 | ошибка параметров CLI |
| 65 | ошибка разбора JSON при `--compare` |
| 66 | файл сравнения недоступен |
| 69 | отсутствует обязательная зависимость операции, например `python3` для `--compare` |
| 73 | явный путь сохранения корпоративного отчёта недоступен |

## Стандартный JSON — schema v1

```bash
sudo arm_info --json --privacy
```

Стандартный JSON содержит `schema_version`, системные показатели, scores, confidence, diagnostics и массив `recommendations[]`.

Начиная с 1.2.3 объект `storage` разделяет типы накопителей: системные, дополнительные внутренние и съёмные. Это позволяет автоматизации отличить неполную проверку системного диска от подключённой USB-флешки. Съёмные носители не должны делать `storage.known=false` и не участвуют в `storage.score`.

Объект `stability` в 1.2.3 содержит итоговую оценку и данные о факторах/штрафах, используемых для `Стабильности системы`. Это позволяет объяснить снижение score программно, а не только по текстовому отчёту.

Пример:

```bash
sudo arm_info --json --privacy | jq '.summary'
sudo arm_info --json --privacy | jq '.storage'
sudo arm_info --json --privacy | jq '.stability'
```

## Корпоративный JSON — schema v2

```bash
sudo arm_info --corp --privacy --json
```

Корпоративная schema v2 содержит стабильные ключи в `checks[]`, сводку и расширенные `recommendations[]`. Это основной формат для helpdesk, сравнения АРМ и последующей машинной обработки корпоративной диагностики.

Кандидат 1.3 сохраняет schema v2, но добавляет новые mail/DC/resource checks. Потребитель должен сопоставлять элементы по стабильному ключу, а не ожидать фиксированное число или позицию строк. Исчерпание общего сетевого бюджета не удаляет обнаруженный объект: его check остаётся в JSON со статусом N/A/unknown и причиной.

По умолчанию ни стандартный, ни корпоративный запуск файл не создаёт, поэтому JSON безопасно использовать в pipeline. Для явного сохранения добавьте `--save`; `-o` используется только вместе с `--save`:

```bash
sudo arm_info --corp --privacy --json | jq '.summary'
sudo arm_info --corp --privacy --json --save -o /var/tmp/arm-corp.json
```

## Сравнение двух АРМ

```bash
arm_info --compare arm-a.json arm-b.json
arm_info --compare arm-a.json arm-b.json --json
```

Для корпоративной schema сравниваются стабильные ключи `checks[]`. Для стандартной schema выполняется рекурсивное сравнение с исключением очевидно изменчивых полей времени/отчёта. Код `0` означает отсутствие отличий, `1` — отличия найдены.

Для `--compare` требуется `python3`.

## Рекомендации

В стандартной schema v1 рекомендации содержат причины, влияние, проверки, действие, команду и контроль результата. В schema v2 корпоративного профиля команды представлены массивом `commands[]`, что позволяет обрабатывать каждую команду отдельно без парсинга текстового отчёта.

Текстовый вывод команд не следует использовать как машинный протокол: начиная с 1.2.3 команды печатаются одной физической строкой для безопасного копирования, но для автоматизации предпочтителен JSON.
