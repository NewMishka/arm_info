# arm_info 1.3.0

Дата выпуска: 18 сентября 2026 года.

1.3.0 развивает корпоративную диагностику в универсальный конвейер: сначала собирается полный нормализованный снимок инфраструктурных объектов, затем ограниченные по времени probes, после них — статусы, рекомендации и TXT/JSON. Single-file сценарий `передать arm_info.sh → запустить` сохранён.

## Основные изменения относительно 1.2.4

### DNS и контроллеры домена

- В объединённом enterprise-отчёте устранён повторный раздел DNS; самостоятельный `network` по-прежнему выполняет собственную DNS-проверку.
- Список DC больше не ограничен тремя узлами. Объединяются уникальные цели из Kerberos, LDAP и AD DC SRV.
- Каждый обнаруженный DC выводится отдельно со статусами TCP 88/Kerberos и 389/LDAP; сохраняется итог `N из M`.
- Контроллеры — обнаруженные через DNS узлы, а не список «активно подключённых» серверов.
- Если TCP-инструмент недоступен или общий бюджет исчерпан, результат — N/A/UNKNOWN, а не ложный OK.

### SMB, autofs, GVFS и GIO

- CIFS, статические autofs-карты, GVFS/FUSE и пользовательский GIO/D-Bus собираются независимо и объединяются в нормализованный inventory.
- Для каждого ресурса сохраняются origin/source, пользовательский контекст и независимые признаки `configured`, `mounted`, `available`/probe result.
- Все ресурсы остаются построчно в отчёте; одна неисправная шара не скрывает рабочие и не заменяет сводку.
- CIFS TARGET читается одной колонкой, поэтому пробелы и кириллица не ломают разбор. Доступность проверяется полным readdir и metadata lookup одного элемента, а не `stat -f` или первым cached entry.
- `sec=krb5,multiuser` проверяется в контексте активного GUI-пользователя.
- GIO обнаруживает подключения даже без FUSE mount; одинаковые GIO/FUSE представления не дублируются.
- Обычные подпапки внутри открытой шары не считаются отдельными ресурсами: FUSE-список фильтруется по формату GVFS mount descriptor, вложенные GIO URI объединяются по корню `server/share`, а технические CIFS mounts от DFS referrals сворачиваются под верхнеуровневый CIFS-ресурс.
- Статические autofs-карты разбираются как данные и не исполняются. По умолчанию несмонтированные ресурсы показываются пассивно как INFO; `--probe-autofs` явно разрешает чтение, способное вызвать автомонтирование.

### Почтовая диагностика

- Добавлен профиль `--profile mail`; `enterprise`, `--corp` и `-c` теперь включают `domain + network + print + mail`.
- Endpoints обнаруживаются из Thunderbird-совместимых `prefs.js` активного/invoking пользователя или задаются повторяемыми `--mail-endpoint` и `--mail-domain`.
- Для централизованной конфигурации добавлены whitelist-ключи `ARM_INFO_MAIL_ENDPOINTS`, `ARM_INFO_MAIL_DOMAINS`, `ARM_INFO_MAIL_PREFS`.
- Поддерживаются `imaps`, `imap`, `smtps`, `smtp`: DNS, TCP, implicit TLS/STARTTLS, проверка chain/hostname/срока сертификата, pre-auth capabilities/AUTH, MX/SRV.
- Профиль не читает пароли, не аутентифицируется, не получает Kerberos service ticket, не открывает ящик и не отправляет письмо.
- Privacy скрывает mail host/domain и Subject/Issuer сертификата.

### CUPS

- `CUPS warning/error` считает только реальные journal entries severity 0–4 за текущую загрузку. Ноль записей даёт OK, наличие сообщений — WARN, недоступный журнал — N/A.
- Отсутствие default printer не считается ошибкой и остаётся INFO.
- Рекомендации дополнены `lpstat -t`, подробными `lpq`, штатной очисткой одной очереди `cancel -a QUEUE_NAME` или всех очередей `cancel -a`, восстановлением очереди, контролируемым restart и тестовой страницей.
- Все изменяющие состояние действия маркируются `ИЗМЕНЯЕТ СОСТОЯНИЕ` и не выполняются автоматически.
- Небезопасное прямое удаление `/var/spool/cups/*` намеренно не предлагается.

### Ограничение времени и производительность

- `--network-budget SEC` задаёт общий лимит 1–300 секунд (по умолчанию 30) для активных DC/CIFS/autofs/GIO/mail probes.
- `--network-jobs N` задаёт 1–16 параллельных TCP-проверок DC (по умолчанию 4). Результаты выводятся в детерминированном порядке.
- После исчерпания бюджета discovery не прекращается: обнаруженные объекты остаются в отчёте с N/A.
- Safe timeout runner не запускает потенциально зависающую команду без ограничения, если системный `timeout` отсутствует.
- TXT-рендер вычисляет ширину один раз, короткие строки не вызывают `fold`, padding выполняется средствами Bash.
- Свойства NetworkManager кэшируются на время одного сетевого сбора, включая пустые значения и fallback старых `nmcli`.

### CLI и рекомендации

- Добавлен короткий `-p` для `--privacy` во всех корпоративных профилях; описание `-s/--save` выровнено.
- Все новые параметры отражены в `--help`: `--probe-autofs`, `--network-budget`, `--network-jobs`, `--mail-endpoint`, `--mail-domain`.
- Команды CUPS, SMB, Kerberos, 802.1X, RAID и mail проходят общий command-audit. Неактуальный `MOUNT_PATH` удалён из действующего набора токенов.

## Архитектура и совместимость

Внутренний путь корпоративных данных теперь разделён на `collect → normalized inventory → probe → checks/recommendations → output`. Это уменьшает повторные внешние вызовы, отделяет факт обнаружения от доступности и позволяет добавлять способы подключения без специальных веток в renderer.

Форматы standard JSON schema v1 и corporate schema v2 сохранены. Профили, `-c`/`--corp`, opt-in сохранение `-s`, privacy и single-file поставка остаются совместимыми с 1.2.4. Новые checks и ресурсы естественно добавляют строки/элементы в corporate schema v2, поэтому потребители не должны полагаться на фиксированное число проверок.

Реализация не привязана к конкретному числу дисков, DC или SMB-ресурсов и поддерживает разные механизмы монтирования. Полнота зависит от установленных `python3`, DNS tools, `nc`/`nmap-ncat`, `openssl`, `gio`, CUPS clients и доступности пользовательской D-Bus session.

## Проверки и измерения

Автоматический набор проверок выполнен перед выпуском. На целевом АРМ подтверждены почтовый профиль и корректное объединение вложенных CIFS/DFS mounts без ложного вывода подпапок отдельными шарами. Остальные аппаратно- и инфраструктурно-зависимые сценарии перечислены в pre-release checklist без заявления о полном покрытии каждой комбинации РЕД ОС, desktop session и корпоративной инфраструктуры.

Добавлены `test_stage1_performance.sh`, `test_stage2_limits.sh`, `test_stage3_architecture.sh`, `test_enterprise_discovery.sh` и `test_mail_profile.sh`; расширены sections, CIFS и recommendation-command contracts.

Зафиксированные синтетические/контрольные измерения ветки:

- 1000 коротких TXT-строк: 4,042 с → 0,130 с;
- корпоративный TXT в контрольной среде: 0,924 с → 0,435 с;
- 16 синтетических TCP probes: 1,651 с при concurrency 1 и 0,421 с при concurrency 4;
- полный тестовый прогон stage 3: 13,863 с до разделения и 13,825 с после; повтор 14,305 с находится в пределах шума окружения;
- `network` с бюджетом 1 с, среднее пяти запусков: 238,4 мс → 210,8 мс;
- нормализованный JSON `network` в контрольной среде не изменился.

Эти цифры характеризуют тестовое окружение, а не гарантированное время на любом АРМ. Общий бюджет ограничивает активные сетевые probes, но внешние локальные команды и discovery также влияют на полное время.

## Статус полевой проверки

- Пользователь подтвердил работу mail-профиля на одном целевом АРМ.
- На целевом АРМ подтверждено, что вложенные CIFS/DFS mounts и подпапки больше не выводятся как самостоятельные шары.
- Полный runtime-прогон всех сочетаний DC, GIO без FUSE, autofs `--probe-autofs`, CUPS journal и privacy не заявляется. Неподтверждённые сценарии сохранены открытыми в [pre-release checklist](../PRE_RELEASE_CHECKLIST.md).

## Примеры

Корпоративный обезличенный отчёт с увеличенным общим бюджетом:

```bash
sudo bash arm_info.sh -c -p --network-budget 60
```

Активная проверка настроенных autofs-ресурсов (может вызвать автомонтирование):

```bash
sudo bash arm_info.sh -c -p --probe-autofs
```

Явная почтовая проверка:

```bash
sudo bash arm_info.sh --profile mail \
  --mail-endpoint imaps://imap.example.test:993 \
  --mail-endpoint smtp://smtp.example.test:587 \
  --mail-domain example.test
```

Сохранение остаётся явным: добавьте `-s`, а путь — через `-o`. Без `-s` команды выше только печатают отчёт.

## Артефакты релиза

GitHub Release публикует только готовый single-file скрипт `arm_info.sh` и файл `SHA256SUMS` для проверки загрузки. RPM-пакет в состав артефактов 1.3.0 не входит.
