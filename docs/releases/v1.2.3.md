# arm_info 1.2.3

Версия 1.2.3 улучшает точность оценки накопителей, прозрачность системного индекса и удобство полевой диагностики на корпоративных АРМ РЕД ОС.

## Что изменено

- оценка стабильности переименована в `Стабильность системы`: в отчёте показываются `100/100`, каждый учитываемый сигнал и его штраф; это оценка устойчивости работы АРМ по системным событиям, а не утверждение о повреждении самой ОС;
- исправлена полевая ошибка LVM/device-mapper: имя системного диска очищается от tree-префикса `lsblk`, поэтому root-диск корректно получает роль `Системный`;
- оптические устройства явно выводятся как `Оптический (вне индекса)`;
- 802.1X больше не ограничивается только активными NetworkManager-профилями: проверяются все настроенные профили и отдельно отображается число активных;
- если NetworkManager не возвращает certificate reference, используется безопасный host-named certificate fallback в `/etc/pki/tls`/`/etc/pki/tls/certs`;
- для доступного PEM/DER X.509 выводятся Subject/Issuer, дата начала, дата окончания и остаток срока; поддерживаются основной и phase2 client/CA certificate;
- физический диск корневой ФС определяется через `findmnt` + raw `lsblk -s`, включая типовой LVM/device-mapper;
- системный диск выводится первым с ролью `Системный`;
- USB/съёмные носители имеют роль `Съёмный (вне индекса)` и тип `USB-накопитель`/`Съёмный накопитель`;
- removable media не влияют на storage score, SMART completeness, эксплуатационный возраст и SMART-рекомендации;
- файловые системы съёмных носителей не участвуют в `Макс. заполнение`, inode-score и read-only штрафах;
- системный накопитель имеет 80% веса внутри storage-группы, худший известный дополнительный внутренний — 20%;
- если физический системный диск определить не удалось, сохраняется fallback по внутренним несъёмным накопителям;
- JSON storage содержит отдельные счётчики системных, дополнительных и съёмных накопителей;
- JSON stability содержит факторы и штрафы, чтобы расчёт можно было объяснить программно;
- стандартный блок рекомендаций использует такое же выравнивание полей, как корпоративный;
- команды в рекомендациях выводятся одной физической строкой без принудительного `fold`; терминал может визуально переносить длинную команду, но при копировании она остаётся цельной; пояснение выводится отдельной строкой в скобках;
- корпоративная шапка отображается как `ARM_INFO КОРПОРАТИВНЫЙ`; внутренний ключ профиля `enterprise` и JSON schema v2 сохранены для совместимости;
- `Makefile` больше не хранит отдельную захардкоженную версию: `make version` читает `VERSION`, а `make check`, CI и release workflow сверяют её с `arm_info.sh` и RPM spec.

Цель изменения: подключённая флешка или оптический привод не должны ухудшать оценку технического состояния АРМ, снижать полноту SMART или подменять показатели системного диска/файловой системы; системные оценки должны быть объяснимыми, а команды — безопасными для копирования.

## Полевое подтверждение

На целевом РЕД ОС перед выпуском подтверждено:

- системный NVMe корректно определяется как `Системный`;
- USB-флешка отображается как `Съёмный (вне индекса)` и не влияет на итоговую оценку;
- оптический привод отображается как `Оптический (вне индекса)`;
- блок 802.1X отображает профиль/сертификат и даты действия корректно;
- новый блок `СТАБИЛЬНОСТЬ СИСТЕМЫ` отображается понятно и прозрачно;
- длинные команды из рекомендаций копируются без физического разрыва строки.
