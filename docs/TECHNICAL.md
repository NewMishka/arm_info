# Техническая архитектура

`arm_info` — single-file Bash-утилита. Базовая диагностика, корпоративные профили и `--compare` находятся в одном `arm_info.sh`, чтобы сохранять сценарий «SSH → передать один файл → запустить». Внешние документы и packaging не требуются для самого запуска.

## Режимы

- стандартный анализ — аппаратное/системное состояние с техническим индексом;
- `--profile domain|network|print|software` — отдельные корпоративные read-only профили;
- `--corp` / `--profile enterprise` — объединение `domain + network + print` без глобальной инвентаризации ПО;
- `--compare A.json B.json` — сравнение двух сохранённых JSON-отчётов.

Корпоративные профили не смешиваются с базовым health score: они формируют собственные `OK/INFO/WARN/CRIT/N/A` проверки и рекомендации.

## Источники данных

- `/etc/os-release`, `uname`, `lscpu`, `/proc/cpuinfo`;
- `/proc/meminfo`, `free`, `dmidecode`;
- `/sys/class/net`, `ip`, `resolvectl`/`nmcli`;
- `findmnt`, `df`;
- `systemctl`, `journalctl`;
- `lsblk`, `smartctl`;
- `findmnt` + raw `lsblk -s` для определения физического системного диска через LVM/device-mapper;
- `/sys/class/block/*/removable` и `lsblk TRAN` для отделения съёмных/USB-носителей;
- thermal hwmon и `sensors`;
- `/proc/mdstat`, `/sys/devices/system/edac`, `/sys/class/power_supply`;
- `timedatectl`/`chronyc`, `realm`, `sssctl`, `adcli`, `klist`;
- DNS `dig`/`host`, `openssl`, CIFS/GVFS/GIO, CUPS/`lpstat`;
- `rpm` и `ps` для отдельного software-профиля.

## Принципы

1. Диагностика сама не изменяет конфигурацию системы.
2. Команды, способные изменить состояние, могут присутствовать в рекомендациях только как явно описанные действия и никогда не выполняются автоматически.
3. Неизвестный показатель не считается исправным автоматически.
4. Метрики нормализуются там, где абсолютные счётчики вводят в заблуждение, например network ppm.
5. Рекомендации объясняют причины, влияние, порядок проверки, действие, команды и контроль результата.
6. Длинный обычный текст переносится по ширине терминала с сохранением выравнивания. Команды в рекомендациях печатаются одной физической строкой; терминал может переносить их только визуально, поэтому копирование не разрывает pipeline и аргументы.
7. Shell pipeline и регулярные выражения с `|` в корпоративных рекомендациях сохраняются как единая команда, а не дробятся по каждому символу `|`.
8. Privacy применяется к пользовательскому выводу, инфраструктурным идентификаторам и автоматически сформированному имени отчёта.
9. Конфигурация парсится whitelist-механизмом, без `source`.
10. `Makefile` не содержит отдельной версии: значение читается из `VERSION`, а `make check` сверяет его с `arm_info.sh` и RPM spec.

## Температура CPU

В стандартном анализе выполняются до трёх коротких замеров. Для оценки и пользовательского вывода используется медиана. Это уменьшает влияние единичного температурного выброса на отчёт.

## Стабильность системы

Группа `Стабильность системы` начинается со 100 баллов и имеет вес 15% в общем индексе. В неё входят runtime-сигналы: failed systemd units, hardware/storage errors из kernel journal, уникальные `err..alert`, OOM, синхронизация времени, признаки аварийной загрузки и ECC/EDAC.

Текстовый отчёт показывает каждый сигнал и его штраф отдельно. Это оценка устойчивости работы АРМ по системным событиям, а не утверждение о повреждении или качестве установленной ОС. Подробная таблица штрафов находится в `docs/SCORING.md`.

## Накопители 1.2.3

Физический накопитель корневой файловой системы определяется как системный и имеет приоритет в storage score. Raw-вывод `lsblk` используется специально, чтобы tree-префиксы (`└─`, `├─`) не попадали в имя устройства при LVM/device-mapper.

USB/съёмные накопители и оптические устройства остаются видимыми в инвентаризации, но помечаются `вне индекса`; они не влияют на storage score, SMART completeness, эксплуатационный возраст и оценку заполненности внутренних файловых систем.

## 802.1X 1.2.3

Сетевой профиль проверяет все настроенные NetworkManager connections, а не только активные. Для PEM/DER сертификатов выводятся Subject, Issuer, `notBefore`, `notAfter` и остаток срока. Значения `file://` читаются без escape. PKCS#11/blob фиксируются как источник без интерактивного запроса PIN.

Если NetworkManager не возвращает certificate reference, допустим безопасный fallback-поиск host-named X.509 в `/etc/pki/tls`; такой сертификат помечается кандидатом, пока связь с конкретным профилем не подтверждена.

## Сохранение отчётов

Стандартный анализ сохраняет TXT/JSON по умолчанию. С `1.2.2` такое же поведение применяется к `--corp` / `--profile enterprise`; `--no-save` отключает запись, а `-o/--output` задаёт файл или каталог.

Отдельные корпоративные профили без `-o` могут использоваться как терминальные диагностические команды и автоматически файл не создают.

## JSON

- стандартный анализ: schema v1;
- корпоративные профили: schema v2 со стабильными `checks[]` и расширенными `recommendations[]`;
- `--compare --json`: отдельный компактный результат сравнения.

Schema version хранится в поле `schema_version`. При несовместимом изменении структуры номер должен быть увеличен.

## Ограничения

Vendor-specific SMART не стандартизирован. Температура зависит от драйверов. Power-On Hours не равен календарному возрасту. Отсутствие Kerberos-билета в root-контексте не говорит о пользовательской сессии. Software RAID проверяется только для Linux md. Автоматические syntax/tests в Ubuntu/Fedora/Rocky не заменяют runtime-проверку на реальной РЕД ОС.
