# Техническая документация

## Архитектура

`arm_info.sh` — автономный Bash-скрипт без собственного демона, базы данных или конфигурационного файла. Все проверки выполняются локально и только на чтение, за исключением создания TXT-отчёта.

Скрипт заключён во вложенную Bash-оболочку. Это позволяет безопасно вставлять его целиком в уже открытый root-терминал: перенаправление вывода через `tee` действует только внутри скрипта и не остаётся активным после завершения.

## Основные источники данных

| Данные | Источник |
|---|---|
| ОС | `/etc/os-release` |
| Ядро / архитектура | `uname` |
| CPU topology | `lscpu`, `/sys/devices/system/cpu` |
| Load Average | `/proc/loadavg` |
| CPU temperature | `/sys/class/hwmon`, `/sys/class/thermal`, опционально `sensors` |
| RAM / swap | `/proc/meminfo`, `free` |
| Модули RAM | `dmidecode -t memory` |
| Сеть | `ip`, `/sys/class/net`, `resolvectl`/`nmcli` |
| Файловые системы | `findmnt`, `df` |
| systemd units | `systemctl --failed` |
| journal/kernel errors | `journalctl` |
| SMART | `smartctl` |
| DMI/BIOS | `/sys/class/dmi/id` |

## Безопасность выполнения

Скрипт:

- не изменяет сетевые настройки;
- не перезапускает службы;
- не запускает `fsck`;
- не запускает SMART self-test автоматически;
- не удаляет файлы;
- не меняет конфигурацию ОС;
- создаёт только TXT-отчёт.

Рекомендованные команды выводятся как текст и не выполняются автоматически.

## Почему нужен root

Без root часть `smartctl`, `dmidecode` и системных журналов может быть недоступна. Скрипт продолжит работу, но снизит показатель полноты диагностики.

## Совместимость

Основная целевая среда — РЕД ОС 7.x/8.x. Скрипт старается не зависеть от локализации вывода: там, где это важно, используется `LC_ALL=C` или машинно-читаемые интерфейсы `/proc` и `/sys`.

## Формат отчёта

Имя файла:

```text
ARM_INFO_<hostname>_<timestamp>.txt
```

Каталог — текущий рабочий каталог. При невозможности записи используется `/tmp`.

## Диагностические ограничения

1. Не все SATA SSD публикуют универсальный процент остаточного ресурса.
2. USB/SATA bridges могут скрывать SMART.
3. Некоторые аппаратные платформы не публикуют CPU temperature стандартными драйверами.
4. `Power On Hours` относится к конкретному накопителю, а не ко всему системному блоку.
5. Дата установки ОС может быть приблизительной, если birth time корневой ФС недоступен и используется наиболее ранний RPM install time.
