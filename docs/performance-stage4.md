# Четвёртый этап: конвейер стандартного отчёта

База этапа: `01a29bec` (`main`, после выпуска 1.3.0).

## Архитектура

Стандартная аппаратно-системная диагностика внутри single-file `arm_info.sh`
теперь выполняется явным конвейером:

1. `collect_base_snapshot` собирает и нормализует данные ОС, CPU, памяти,
   сети, файловых систем, журналов, служб, RAID/ECC, батареи и SMART;
2. `evaluate_base_snapshot` вычисляет групповые оценки, полноту, состояние,
   заключение и рекомендации;
3. `prepare_base_output_view` применяет privacy к представлению снимка;
4. выбирается ровно один renderer: `emit_base_text` или `emit_base_json`.

SMART-факты каждого внутреннего диска сохраняются в `DISK_CHECK_ROWS`.
`evaluate_base_disk_findings` формирует из них рекомендации в прежнем порядке.
Collector больше не вызывает `add_rec`. Наличие `smartctl` и UID определяются
один раз, поэтому emitters не повторяют probes среды.

Корпоративные collectors и нормализованный снимок CIFS/autofs/GVFS/GIO этапа 3
не менялись.

## Совместимость

- версия остаётся 1.3.0 до отдельного решения о следующем релизе;
- standard JSON сохраняет schema v1 и прежний набор групп/полей;
- TXT-разделы, тексты рекомендаций, scoring и exit codes сохранены;
- `--privacy`, `--save`, quiet-режим и выбор каталога отчёта выполняются как
  раньше;
- поставка остаётся однофайловой.

## Регрессии

`tests/test_stage4_base_pipeline.sh` проверяет функции и порядок стадий,
запрещает `add_rec` в collector и повторные системные probes в renderers,
а также воспроизводит рекомендации для HDD/NVMe из нормализованных строк.
Прежние `test_cli.sh` и `test_sections.sh` продолжают проверять реальный TXT,
JSON schema v1, privacy, рекомендации и пользовательские разделы.

## Контрольный замер

Среда разработки, 18 сентября 2026 года; три последовательных запуска
`bash arm_info.sh --json --privacy`, медиана:

| Вариант | Медиана |
|---|---:|
| До этапа 4 (`01a29bec`) | 1,112 с |
| После этапа 4 | 1,001 с |

Нормализованный JSON до и после совпал полностью после исключения только
времени генерации, текущего load average и сетевых счётчиков, которые меняются
между последовательными запусками. Верхнеуровневые ключи, ключи всех групп,
schema v1 и exit code совпали. Замер не доказывает ускорение на любом АРМ, но
регрессии быстродействия в контрольной среде не показал.
